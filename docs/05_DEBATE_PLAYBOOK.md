# 05 - Debate playbook

Every afternoon: **Team Battle of Debate** against another team on the same topic. Faculty may question anyone.
Scoring per individual (max 25): Content Knowledge 5, Communication 5, Faculty Q&A 5, Team Coordination 5,
Time Management 5. **Minimum 20/25 per person.** So the debate is won by four people being solid, not by one star.

## 1. Rules of engagement for our team

1. **Everyone speaks**, in the order that follows the pipeline: Role 3 (data + what the system is) → Role 2 (what the data/text/time-series looks like) → Role 1 (model) → Role 4 (evidence and honest limits). Role 3 closes with the live demo.
2. **One claim = one number = one file.** Never say a number that is not in `claims/CLAIMS_LEDGER.md`. If a faculty member asks "where does that come from?", the answer is a file path.
3. **State the limitation first.** "This is calibrated simulation, so absolute accuracy is not production accuracy; what we can show is the comparison with baselines." Said by us, it is honesty; found by them, it is a hit.
4. **Do not attack people; attack claims**, using the questions in section 4.
5. **Time:** rehearse a 90-second opening and 30-second answers. Role 4 keeps the clock.
6. **If we do not know:** "We have not measured that; here is what we did measure, and here is how we would measure it." Never bluff.

## 4. The question bank (Faculty Q&A) - rehearse answers aloud

Answer template: **claim → evidence → limitation (one sentence each)**. Bracketed items are filled from the ledger.

### General
1. *Is the data real?* Calibrated simulation anchored to public real data [IMF PortWatch, NY Fed GSCPI, Open-Meteo]. Every row has `data_origin`. Absolute scores are not production scores; comparisons are the finding.
2. *How do I know there is no data leakage?* Label is the realised outcome, not a function of the features; forbidden-feature policy is enforced in code; split is chronological with a 168-hour purge; shuffle-label test gives [chance]; no single feature has AUC above [0.95] (`eval_leakage_tests.json`).
3. *What is a false alarm worth?* Cost matrix in `contracts/cost_policy.json`: missed critical = 10, unnecessary reroute = 1; threshold chosen on validation, reported on test; sensitivity from 3:1 to 40:1.
4. *Why not just one big model?* Different questions need different tools: tabular now-risk (trees), sequence+network next-days (LSTM/GNN), text (NER), edge text generation (LoRA SLM). Fusion is a transparent logistic model.
5. *What would you do with real data?* Replace `data/raw/sim` by a connector that emits the same contracts; everything downstream is unchanged. Re-calibrate, re-validate thresholds with operators.
6. *Who decides?* The human operator. Every response carries `requires_operator_review: true`; no code executes a reroute.
7. *How did four people integrate without conflicts?* Contracts + file ownership + hooks + CI. Show `python scripts/board.py` and the CI history.

### Stage 1 (ML)
- *Why XGBoost?* Tabular, mixed types, interactions, fast, calibrated afterwards; we also report logistic regression and a rule baseline so you can see what it adds.
- *Class imbalance?* Class weights / sample weights, PR-AUC for Critical, cost-based decision, not accuracy.
- *Isolation Forest vs One-Class SVM?* Unsupervised anomaly scores trained on normal shipments; evaluated against the known Critical shipments by ROC-AUC/precision@k; they flag the *unusual*, the classifier says *how delayed*.
- *Feature importance?* SHAP + permutation importance on the test split; top drivers are [customs hold, utilisation, ...]; agree between methods [yes/no].

### Stage 2 (DL)
- *Why LSTM and not Transformer?* [Result of the comparison]; small data, 72-hour windows, CPU budget. Persistence and seasonal-naive are the baselines.
- *What does the GNN add?* Ablation: with vs without graph, and with a shuffled graph (should hurt). Lead-lag evidence from cross-correlation between linked nodes.
- *How far ahead do you warn?* Median lead time [h] before episode onset at false-alarm rate [x/week].
- *Peak-season vs structural bottleneck?* Seasonal component removed (STL); alert on residual exceedance; five ambiguous graphs analysed in `eda_ambiguous_graphs.md`.

### Stage 3 (NLP)
- *How do you evaluate NER fairly?* Hand-labelled gold test set, two annotators, kappa [k]; strict entity-level F1 per type; test messages from templates not seen in training.
- *What is "LA/LB"?* Ambiguous shorthand mapping to two nodes; our resolver returns both and flags ambiguity; in the audit table.
- *Negation ("no delay expected")?* Behavioural tests: minimal pairs; accuracy [x]; known weak spot [y].

### Stage 4 (SLM)
- *What does fine-tuning buy over prompting?* Same test pairs, three systems: template, base prompt, LoRA. Hallucination rate [a/b/c], format compliance [..], latency [..].
- *How do you measure hallucination?* Every number and node in the summary must appear in the source facts (`grounding_check`); unsupported claim rate reported.
- *Is it really offline?* Test sets the offline flag and blocks sockets; demo with Wi-Fi off.
- *Why 2 sentences?* Operator reading time; study of N briefs vs raw alerts: [seconds saved].

### Stage 5 (GenAI)
- *Why CVAE?* Stable on small data, controllable by condition (scenario, severity), cheap on CPU; GAN/diffusion are discussed as alternatives with their failure modes (mode collapse, slow sampling). Simulator shown as comparator.
- *How do you know synthetic data is realistic?* Range and conservation checks (violation rate [..]), distribution and correlation distance, discriminator AUC [..], TSTR score [..].
- *What does the wildcard show?* The first stage to degrade is [S]; recall falls from [a] to [b]; recommended mitigation [..].
